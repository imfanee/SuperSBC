# FreeSWITCH image with G.729 transcoding

The stock `safarov/freeswitch:1.10.12` image ships FreeSWITCH's own
`mod_g729`, which is a **pass-through stub**: it registers G.729 so the codec
can be negotiated and its packets relayed, and it refuses to produce an
encoder or a decoder. Asking it to transcode logs

```
mod_g729.c:102 This codec is only usable in passthrough mode!
switch_core_media.c:16232 Codec G.729 encoder error!
```

and drops the call. This image replaces that stub with `mod_bcg729`, a real
G.729A codec backed by Belledonne Communications' bcg729, so a call that has
to be transcoded into or out of G.729 works. See D-86 in
`docs/DECISIONS.md`.

## What is here

| Path | What it is | Where it came from |
| --- | --- | --- |
| `src/mod_bcg729.c` | the FreeSWITCH module (MPL 1.1) | ported to 1.10.x, reviewed in this repo |
| `src/bcg729/` | the codec library, pinned at **1.1.1** (GPLv3) | <https://github.com/BelledonneCommunications/bcg729> |
| `include/freeswitch/` | FreeSWITCH 1.10.12 build headers | `src/include` of the 1.10.12 release |
| `include/apr/` | the bundled APR headers (`fspr*`) | `libs/apr/include` of the same release |
| `include/teletone/` | libteletone headers | `libs/libteletone/src` of the same release |
| `Dockerfile` | builds the codec and lays it over the base image | |

Everything is vendored so a deploy never waits on GitHub. Two of the headers
(`include/freeswitch/switch_am_config.h` and `include/apr/fspr.h`) are
generated by FreeSWITCH's `configure`; they contain only platform types and
paths, identical on any x86-64 Debian.

## Rules that keep this working

* **The builder must be `debian:12`.** The runtime image is Debian 12
  (glibc 2.36). A module built on a newer distro needs a newer glibc and
  will not load: `version 'GLIBC_2.38' not found`.
* **The vendored headers must match the base image's FreeSWITCH version.**
  The Dockerfile checks `freeswitch -version` and fails the build if the base
  image is no longer 1.10.12, because the headers would then describe a
  different ABI.
* **`mod_g729.so` is deleted from the image**, not just left unloaded, so
  nothing can load the stub by accident. `freeswitch/conf/autoload_configs/modules.conf.xml`
  loads `mod_bcg729` in its place.
* **Both stacks build this image.** `docker-compose.yml` and
  `deploy/live/docker-compose.live.yml` both point at this directory, so dev
  and live run the same codec and `make up` / `make live-up` rebuild it.

## Bumping FreeSWITCH

1. Change the base image in `Dockerfile`.
2. Re-vendor the headers from the matching release:

```sh
docker run --rm -v "$PWD:/out" debian:12 sh -c '
  apt-get -qq update && apt-get -qq install -y curl ca-certificates build-essential \
    autoconf automake libtool pkg-config libssl-dev zlib1g-dev libpcre3-dev libedit-dev \
    libsqlite3-dev libcurl4-openssl-dev libspeexdsp-dev uuid-dev libldns-dev >/dev/null
  # spandsp3 and sofia-sip are required by FreeSWITCH configure even for headers
  ... see git history of this file for the full recipe'
```

The short version: unpack the release, `./bootstrap.sh`, write a `modules.conf`
with a couple of modules so `configure` does not demand every optional
library, `./configure`, then run `libs/apr/configure` to generate `fspr.h`.
Copy `src/include`, `libs/apr/include` and `libs/libteletone/src` here.

3. Rebuild and run the G.729 tests: `make e2e` covers
   `TestG729_ModuleIsTheRealCodec`, `TestG729_TranscodeBothDirections`,
   `TestG729_RelayWhenBothSidesHaveIt` and `TestG729_StableUnderLoad`.

## Licensing

`mod_bcg729.c` is MPL 1.1. bcg729 1.1.1 is **GPLv3** and is linked statically
into the module, so the resulting `mod_bcg729.so` is covered by the GPLv3.
That is fine for running it on your own SBC; if the binary is ever shipped to
a third party, the source has to go with it, which is why bcg729's source is
vendored here rather than downloaded at build time.
