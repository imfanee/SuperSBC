# Roadmap

Features from the specification that are documented rather than built, with the FreeSWITCH mechanism each one would use. Items are ordered by how often a wholesale operator asks for them.

| Feature | Mechanism | Notes |
|---------|-----------|-------|
| TLS on SIP and SRTP on media, per customer and carrier | Ingress profile: `tls=true`, `tls-sip-port`, `tls-cert-dir`, `tls-only=false`; per customer `customer_ips.transport=tls`; egress gateway `register-transport=tls` plus dial string `rtp_secure_media=mandatory` for SRTP; FreeSWITCH bridges SRTP to RTP transparently | Certificates go into a volume mounted at `/etc/freeswitch/tls`; the renderer would add `<param name="register-transport" value="tls"/>` and `sip_secure_media` variables. `carriers.transport` already accepts `tls` and the gateway renderer emits `;transport=tls` |
| SIP scanner and flood protection | Redis counter of `403 IP not authorized` per source in a sliding window; when over the threshold write the address into the rendered `customers` ACL as `deny` and `reloadacl` (or an nftables set for the host network); expire after N minutes | The ACL renderer and the `rejected_auth` CDRs already provide the inputs; `SBC_ACL_MODE=strict` is the cheap first line today |
| Header manipulation rules per customer and carrier | Table `header_rules(owner_type, owner_id, direction, action add/remove/replace, header, value)`; the setup response carries them and Lua applies `sip_h_<name>` on the a-leg and `{sip_h_...}` in the dial string; removal via `sip_h_X-...=` empty and `sip_copy_custom_headers` | `sip_copy_custom_headers=false` and `sip_cid_type=none` already sanitise both legs |
| Privacy header handling | On ingress, `Privacy: id` sets `origination_privacy=hide_name:hide_number` and `caller_id_number=anonymous` on the egress leg; per carrier flag "pass Privacy" adds `sip_h_Privacy` | `customers.trust_pai` is the companion flag for taking the ANI from P-Asserted-Identity |
| 100rel / PRACK per profile | `<param name="enable-100rel" value="true"/>` on the profile (currently false) and `sip_100rel` variable per dial string | Off by default because many wholesale carriers mis-handle PRACK |
| Media bypass per customer/carrier pair | `bypass_media=true` on the a-leg before bridge when both sides allow it; `proxy_media=true` as the middle ground (signalling anchored, media relayed without transcoding) | Needs `media_bypass` flags on customers and carriers and a per-call decision in `Route` |
| DTMF interworking per carrier | Dial string `dtmf_type=rfc2833|info|none` and profile `dtmf-type`; `liberal-dtmf=true` on the profile for inband detection | Column `carriers.dtmf_mode` plus one line in `dialString` |
| Time-of-day and day-of-week routing windows | `route_carriers.window` (cron-like or `mon-fri 08:00-18:00 Europe/London`); `Route` filters carriers outside their window | Pure Go, unit testable |
| Carrier failed attempt charging | `carriers.charge_failed_attempts` exists; billing would rate each attempt with `classification != answered` at the carrier's connect fee | Needs a `cost` ledger entry per attempt |
| Invoices and statements as PDF | `reports.Statement` is the data; render with a Go PDF library on a monthly cron | CSV export exists today |
| STIR/SHAKEN | Pass through `Identity` header (`sip_h_Identity` copy on egress) as a first step; verification and signing need an STI-VS/AS integration | Not started |
| High availability | Two SBC hosts behind a VIP (keepalived, VRRP); Postgres primary and streaming replica with automatic failover (Patroni or a managed service); Redis Sentinel; the Go API is stateless and can run on both hosts. FreeSWITCH call state is not replicated: in-flight calls drop on failover, reservations are released by the reconciliation worker on the surviving node within `orphan_timeout` | Documented honestly: FreeSWITCH has no shared call state without commercial extensions |
| HEP/HOMER capture | Uncomment `capture-server` in `sofia.conf.xml` and set `sip-capture=yes` on both profiles; FreeSWITCH sends HEPv3 to HOMER | The SIP trace toggle in the UI is the built-in alternative |
| Rate deck versioning and diff | `effective_from`/`effective_to` already allow future decks; a UI diff between two imports is not built | |
| Per-attempt PDD from the b-leg | `uuid_dump` of the b-leg is not available after the bridge returns; the current PDD attribution uses the a-leg progress timestamps (D-29) | An ESL listener on b-leg `CHANNEL_PROGRESS` could store exact times per attempt |
| Email and webhook delivery of notifications | `notifications` rows are written (low balance); a delivery worker with SMTP/webhook config would consume them | |
| Least cost routing with quality weighting | LCR mode orders by buy rate; a quality score (ASR, PDD from the roll-ups) could be blended in | |
| Number portability lookup | An external ENUM/HTTP query before Step 3 (`npdi`, `rn` parameters) | |
